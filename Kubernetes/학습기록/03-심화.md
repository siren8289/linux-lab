# 심화 — 보안, 정책, 스케줄링, Ingress

## ResourceQuota

`study` 쿼터는 파드 10개, `requests.cpu` 1, `requests.memory` 256Mi다. `requests.cpu`와 `requests.memory`가 쿼터에 있으면, 그 네임스페이스의 컨테이너는 해당 request를 적어야 한다.

요청이 없는 `hello`를 먼저 적용했을 때의 오류:

```text
pods "hello" is forbidden: failed quota: study: must specify requests.cpu for: nginx; requests.memory for: nginx
```

`hello`에 `cpu: 10m`, `memory: 16Mi`를 넣은 뒤 적용은 통과했다. 그때 사용량:

```text
pods: 5/10, requests.cpu: 130m/1, requests.memory: 112Mi/256Mi
```

`hello`를 지운 뒤:

```text
pods             4     10
requests.cpu     120m  1
requests.memory  96Mi  256Mi
```

`web` 컨테이너는 request `cpu 50m`, `memory 32Mi`와 memory limit `64Mi`를 가진다. limit은 쿼터 표의 LIMIT 칸을 쓰지 않았다. 쿼터가 limit 합계를 제한하지 않기 때문이다.

## RBAC

ServiceAccount `reader`에는 Role `pod-reader`가 묶여 있다. 권한은 core API의 `pods`에 대한 `get`, `list`뿐이다.

```text
list_pods=yes
list_secrets=no
```

`kubectl auth can-i`는 거절일 때 exit 1이다. 스크립트는 그 종료 코드를 실패로 보지 않도록 `|| true`를 붙였다. 첫 버전은 여기서 멈췄다.

## Pod Security

네임스페이스 라벨은 `pod-security.kubernetes.io/enforce: baseline`이다. `privileged: true` 파드:

```text
Error from server (Forbidden): pods "privileged" is forbidden:
violates PodSecurity "baseline:latest": privileged
(container "nginx" must not set securityContext.privileged=true)
privileged_apply_exit=1
```

파드는 만들어지지 않았다. baseline은 특권 컨테이너를 막는다.

## 스케줄링

`unschedulable`은 `nodeSelector: disk=nonexistent`를 가진다. control-plane toleration이 있어도 노드 이름과 맞지 않으면 Pending이다.

```text
Node-Selectors:  disk=nonexistent
Warning  FailedScheduling  default-scheduler
0/1 nodes are available: 1 node(s) didn't match Pod's node affinity/selector.
preemption: 0/1 nodes are available: 1 Preemption is not helpful for scheduling.
```

스케줄러는 맞는 노드가 없으면 우선순위가 낮은 파드를 밀어내도 자리가 생기지 않는다고 본다. 이 파드는 일부러 그대로 두어 Pending을 확인했고, 클러스터를 지우며 함께 없어졌다.

## HPA

`autoscaling/v2` HorizontalPodAutoscaler `web`은 CPU 평균 사용률 50%, 최소 2, 최대 4다.

```text
web   Deployment/web   cpu: <unknown>/50%   2   4   2
AbleToScale    True    SucceededGetScale
ScalingActive  False   FailedGetResourceMetric
the server could not find the requested resource (get pods.metrics.k8s.io)
```

HPA 컨트롤러는 Deployment의 현재 스케일을 읽었다. metrics-server가 없어 `pods.metrics.k8s.io`가 없고, 레플리카 수를 계산하지 못했다. 파드는 2개로 유지되었다. 메트릭 없이 HPA 객체만 만들어도 스케일은 움직이지 않는다.

## Ingress

```text
Ingress Class: <none>
Address:
Host             Path  Backends
web.study.local  /     web:80 (10.244.0.5:80,10.244.0.10:80)
Events:          <none>
```

Ingress 객체는 Service `web`의 80번 포트로 경로 `/`를 가리킨다. Address가 비어 있고 IngressClass가 없다. 이 클러스터에는 Ingress 컨트롤러를 설치하지 않았다. 객체는 API에 저장되고, `web.study.local`로 들어오는 트래픽을 받아 줄 프로세스는 없다. 클러스터 안에서의 접속은 Service DNS로 확인했다.

## Helm과 확장

```text
helm: command not found
helm_exit=127
```

Helm은 설치하지 않았다. 같은 선언 묶음은 `kustomization.yaml`과 `kubectl apply -k`로 적용했다. `kubectl explain deployment`는 `Deployment enables declarative updates for Pods and ReplicaSets.`를 출력했다.
