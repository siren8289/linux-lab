# 중급 — 워크로드, 서비스, 구성, 스토리지

네임스페이스는 `study`다. `kubectl apply -k manifests`로 한 번에 적용했다. Kustomize는 kubectl v1.37.1에 포함된 v5.8.1이다.

control-plane 노드에 일반 파드가 올라가도록 각 파드에 다음 toleration을 넣었다.

```yaml
key: node-role.kubernetes.io/control-plane
operator: Exists
effect: NoSchedule
```

## Deployment와 ReplicaSet

`web`은 파드 2개를 유지한다. 통과 실행:

```text
deployment.apps/web   2/2     2            2
replicaset.apps/web-d7496596b   2         2         2
pod/web-d7496596b-2jjp5   1/1     Running
pod/web-d7496596b-qrnh8   1/1     Running
```

ReplicaSet이 파드 이름을 만들고, Deployment가 ReplicaSet의 개수를 맞춘다. 파드 하나를 지운 뒤에도 ReplicaSet 이름은 그대로였고 새 파드 `web-d7496596b-hhl79`가 Running이 되었다.

```text
deployment "web" successfully rolled out
```

## 컨트롤러가 없는 Pod

`hello`는 Deployment에 속하지 않는다. 삭제 결과:

```text
pod "hello" deleted from study namespace
Error from server (NotFound): pods "hello" not found
HELLO_NOT_RECREATED exit=1
```

같은 시각 Deployment 파드는 대체되었다. 선언의 주인(컨트롤러)이 있을 때만 개수가 복구된다.

## DaemonSet과 Job

노드는 하나라 DaemonSet `logger`의 DESIRED는 1이고 READY도 1이었다.

`web`이 준비된 뒤 Job `once`를 적용했다. 컨테이너는 `wget -qO- http://web.study.svc.cluster.local/`이다.

```text
job.batch/once condition met
study-web
```

Job 파드는 끝나고 다시 떠 있지 않다. 완료된 파드는 아래 Quota 사용량에 포함되지 않은 채로 `pods 4/10`이 나왔다. 그 시점의 Running·Pending은 web 2개, logger 1개, unschedulable 1개다.

## Service

```text
service/web   ClusterIP   10.96.29.182   80/TCP
endpoints/web   10.244.0.5:80,10.244.0.6:80
```

ClusterIP는 파드 IP와 다르다. 파드 안에서:

```text
kubectl exec -n study deploy/web -- wget -qO- http://web.study.svc.cluster.local/
study-web
```

파드를 교체한 뒤 `127.0.0.1`의 wget도 `study-web`이었다. Service 이름과 셀렉터 `app=web`이 새 파드 IP를 엔드포인트에 다시 넣는다. Ingress describe에는 교체 후 주소 `10.244.0.5:80,10.244.0.10:80`이 보였다.

이 Service는 클러스터 안에서만 연다. 호스트 `8080`으로 노출하지 않았다.

## ConfigMap과 Secret

ConfigMap `web-config`의 `index.html`은 `study-web`이다. 파드는 그 키를 `/usr/share/nginx/html/index.html`에 `subPath`로 마운트한다. wget 결과가 그 내용이다.

Secret `web-secret`은 `stringData.token`이 `study-token`이다. 마운트 확인:

```text
kubectl exec -n study deploy/web -- cat /etc/study/token
study-token
```

이 값은 실습용 문자열이다. 계정 키가 아니다. Secret 매니페스트는 그 값을 그대로 적으므로 배포용 저장 방식은 아니다.

## emptyDir

`web`의 `/scratch`는 emptyDir이다. 한 파드에 `scratch-note`를 쓰고 그 파드를 지웠다.

```text
write_pod=web-d7496596b-2jjp5
scratch-note
read_pod=web-d7496596b-hhl79
cat: can't open '/scratch/note': No such file or directory
EMPTYDIR_GONE exit=1
```

새 파드의 디스크는 이전 컨테이너 쓰기 영역을 이어받지 않는다. ConfigMap으로 만든 `study-web` 페이지는 파드가 바뀌어도 남는다. 그 데이터는 파드 디스크가 아니라 API의 ConfigMap에 있기 때문이다.

## PVC

kind 생성 로그에 `Installing StorageClass`가 있다. PVC `data`는 1Gi, ReadWriteOnce다. 상태를 소비하는 파드는 만들지 않았다.

```text
persistentvolumeclaim/data   Pending   STORAGECLASS standard
```

describe 이벤트:

```text
Status:        Pending
Normal  WaitForFirstConsumer  persistentvolume-controller  waiting for first consumer to be created before binding
```

StorageClass 이름은 `standard`다. 컨트롤러는 프로비저너가 없어서가 아니라, 첫 소비자 파드를 기다리며 바인드를 미루고 있다. 용량과 액세스 모드는 아직 비어 있다.
