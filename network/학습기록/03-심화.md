# Part 3. 심화

## 11. L4 / L7 로드밸런서

L4는 IP와 포트, 연결 정보로 나눈다. AWS NLB가 이 층이다. L7은 Host, 경로, 헤더를 본다. AWS ALB와 Nginx가 이 층이다.

### 실행

백엔드 파일을 만들었다.

```text
네트워크/backend-a/index.html    Backend A
네트워크/backend-b/index.html    Backend B
```

`nginx`와 `apt`가 없어 `/etc/nginx`에는 설정을 넣지 않았다. 교재와 같은 upstream 문서는 `네트워크/nginx/lab-lb.conf`에 남겨 두었다.

```nginx
upstream lab_backend {
    server 127.0.0.1:8001;
    server 127.0.0.1:8002;
}
server {
    listen 127.0.0.1:8088;
    location / {
        proxy_pass http://lab_backend;
    }
}
```

실제로 8088을 받은 프로세스는 `네트워크/scripts/lab_lb.py`다. `127.0.0.1:8001`과 `8002`를 번갈아 호출하고, 고른 쪽이 연결을 거부하면 다른 쪽에 한 번 더 보낸다. 응답 헤더 `X-Lab-Backend`에 실제로 응답한 쪽을 적는다.

`네트워크/scripts/test-lb.sh` 결과:

```text
[Response count]
   5 Backend A
   5 Backend B
PASS: Both backends responded
```

종료 코드 0. 5:5는 이번 10회 순차 요청의 결과이고, 항상 반반이라는 보장은 아니다.

백엔드 A(`8001`)를 종료한 뒤 같은 URL을 네 번 호출했다.

```text
HTTP/1.1 200 OK
X-Lab-Backend: http://127.0.0.1:8002
Backend B
```

네 번 모두 B였다. Nginx 기본 설정은 `max_fails` 때문에 죽은 upstream을 잠시 빼는데, 이번 프록시는 연결 거부가 나오면 그 요청에서 바로 다른 백엔드를 시도한다. 분산이 된다는 검증과, A가 죽어도 B가 응답한다는 검증은 됐다.

실습이 끝난 뒤 8001, 8002, 8088 프로세스는 종료했다.

## 12. tcpdump

`tcpdump -D`는 비밀번호 없이 인터페이스 목록을 냈다. `lo0`는 11번, `en0`는 2번이다.

캡처는 실패했다.

```text
tcpdump: lo0: You don't have permission to capture on that device
((cannot open BPF device) /dev/bpf0: Permission denied)
```

`sudo -n tcpdump`는 `a password is required`에서 멈췄다. pcap 파일은 만들지 않았다. 인증 정보가 들어갈 수 있는 캡처를 Git에 넣지 않는다는 교재 주의는 그대로 따른다.

그래서 handshake의 플래그(`[S]`, `[S.]`, `[.]`)는 패킷으로 보여 주지 못했다. 대신 연결을 유지한 채 `netstat`으로 `LISTEN`과 `ESTABLISHED`를 확인했다. 자세한 줄은 [02-중급.md](02-중급.md)에 있다.
