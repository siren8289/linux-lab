# 중급 — 값, State, Plan, Module

## 값을 다루는 네 가지

| 구성 | 이번 실습에서 한 일 |
|---|---|
| `variable` | `student_name` 기본값 `Terraform`. `-var`와 `TF_VAR_student_name`으로 덮어씀 |
| `locals` | `file_label = terraform-study-Terraform` |
| `output` | `file_path`, `file_content`, `file_label`, `existing_file_content` |
| `data` | `data.local_file.existing`가 `hello.txt`를 읽음 |

`terraform output -json`에서 네 값 모두 `"sensitive": false`였다. `sensitive = true`는 화면에 숨기는 표시이고, State 파일을 암호화하지는 않는다. 이번 값에는 비밀이 없다.

## 변수 우선순위

같은 State에서 plan만 비교했다. 적용은 Linux 저장 plan 한 번뿐이다.

| 입력 | plan의 내용 | `file_label` |
|---|---|---|
| 기본값 | `Hello, Terraform!` | `terraform-study-Terraform` |
| `-var='student_name=Docker'` | `Hello, Docker!`, `forces replacement` | `terraform-study-Docker` |
| `TF_VAR_student_name=AWS` | `Hello, AWS!`, `forces replacement` | `terraform-study-AWS` |
| 환경 변수 AWS와 `-var` Docker를 같이 | `Hello, Docker!` | `terraform-study-Docker` |

내용이 바뀌면 `local_file`은 그 자리에서 수정하지 않고 `-/+` 교체로 계획했다.

```text
# forces replacement
- Hello, Terraform!
+ Hello, Docker!
Plan: 1 to add, 0 to change, 1 to destroy.
```

`-var`가 같은 실행의 `TF_VAR_student_name`보다 우선했다.

## 저장한 Plan

```text
terraform plan -var='student_name=Linux' -out=study.tfplan
terraform apply study.tfplan
```

적용 결과:

```text
local_file.study: Destruction complete after 0s
local_file.study: Creation complete after 0s [id=be3183d1cf53c3ce86f4a2606d4d773a88b9e872]
Apply complete! Resources: 1 added, 0 changed, 1 destroyed.
file_content = Hello, Linux!
file_label = "terraform-study-Linux"
```

`hello.txt`는 `Hello, Linux!`가 되었다. `study.tfplan`은 확인 후 삭제했다. Plan 파일에도 값이 들어가므로 Git에 올리지 않는다. 이 저장소 자체는 Git이 아니다.

Drift 실습 전에 기본값으로 다시 apply해서 파일을 `Hello, Terraform!`로 되돌렸다. 그때의 apply 출력은 스크립트가 `/dev/null`로 보냈고, 다음 줄이 결과를 보여 준다.

```text
before: Hello, Terraform!
```

## State

`terraform state show`는 파일 내용, SHA1 ID, 권한 `0777`, 경로 `./hello.txt`를 저장하고 있었다. `terraform output -json`의 `file_content` 값은 `Hello, Terraform!\n`이다.

State는 “명령을 실행했다”는 로그만이 아니다. 다음 plan은 이 ID로 실제 파일을 다시 읽고, 코드와 다르면 작업을 계산한다.

## 의존성

`terraform graph`에서 파일 리소스 쪽 간선:

```text
"data.local_file.existing" -> "local_file.study";
```

Data Source가 `local_file.study.filename`을 참조하고 `depends_on`도 있어서, 읽기는 파일 리소스 뒤에 온다. AWS 예시의 `aws_subnet.public`이 `aws_vpc.main.id`를 참조하면 같은 방식으로 순서가 생긴다. `depends_on`은 참조만으로 순서가 보이지 않을 때 쓴다.

## Module

`modular/modules/app-config`는 `name`과 `port`를 받아 `local.config`로 묶고 그대로 출력한다. 리소스 블록이 없다.

```text
- api in modules/app-config
Success! The configuration is valid.
Apply complete! Resources: 0 added, 0 changed, 0 destroyed.
api_config = {
  "name" = "study-api"
  "port" = 8080
}
```

`terraform output`도 같은 맵을 한 번 더 출력했다. 모듈은 리소스를 반드시 만들지 않아도 입력과 출력을 재사용할 수 있다. 이 State에는 출력만 남는다.
