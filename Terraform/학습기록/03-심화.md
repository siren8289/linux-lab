# 심화 — Backend, Drift, Lifecycle, Import, 보안

## Backend와 잠금

이번 실습의 State는 전부 로컬 `terraform.tfstate`다. S3 버킷과 HCP Terraform은 만들지 않았고, `backend "s3"`로 `terraform init`도 하지 않았다.

HashiCorp S3 Backend 문서(2026-10-29에 확인)의 잠금 설명은 다음과 같다.

- 잠금은 선택이다.
- `use_lockfile = true`이면 State와 같은 위치에 `.tflock` 파일을 둔다.
- DynamoDB 잠금(`dynamodb_table`)은 폐기 예정이고, 이후 마이너 버전에서 제거된다.
- 둘을 같이 적을 수는 있다. 신규 구성의 권장 잠금은 S3 lockfile 쪽이다.

협업에서는 같은 State를 동시에 고치지 않도록 잠금을 쓰고, 저장소 권한·암호화·버전 관리를 둔다. 로컬 파일만 쓰는 이번 학습에는 그 원격 잠금이 없다.

## Drift

Linux plan을 적용한 뒤 기본값으로 되돌리고, Terraform 밖에서 파일을 고쳤다.

```text
before: Hello, Terraform!
drifted: Manual modification
```

plan은 내용 수정이 아니라 삭제로 읽었다.

```text
Note: Objects have changed outside of Terraform
# local_file.study has been deleted
- filename = "./hello.txt" -> null
  id       = "ae9c7cc6581fe6b7a01af3ee5fa123a4afc9bac1"
# local_file.study will be created
Plan: 1 to add, 0 to change, 0 to destroy.
```

`hashicorp/local` v2.9.1은 파일 내용이 State의 ID(내용 SHA1)와 다르면 관리 객체가 사라진 것으로 본다. 변수로 내용을 바꾼 plan은 `-/+` 교체였고, 사람이 파일을 덮어쓴 plan은 `+ create`였다. Provider와 변경 위치에 따라 표시가 달라진다.

복구 apply:

```text
local_file.study: Creation complete after 0s [id=ae9c7cc6581fe6b7a01af3ee5fa123a4afc9bac1]
Apply complete! Resources: 1 added, 0 changed, 0 destroyed.
repaired: Hello, Terraform!
```

파일 바이트는 다시 `b'Hello, Terraform!\n'`이다. 첫 실행 스크립트는 이 줄을 `FAIL`로 기록했다. 파일은 복구되어 있었고, 비교 조건이 `$(cat)`이 지우는 줄바꿈까지 요구했다. 조건은 그 뒤 고쳤다. 자세한 내용은 [troubleshooting.md](troubleshooting.md)에 있다. 전체 러너는 그 수정 후 다시 돌리지 않았다.

## Lifecycle

`lifecycle/`에서 두 파일을 만들었다.

| 리소스 | 내용 | id |
|---|---|---|
| `local_file.kept` | `keep` | `0c251ef2fca485fd117c165c8a20692c0f1c7220` |
| `local_file.quiet` | `one` | `c7059bb19433cc3cabaa6236c83d56668a843dd2` |

`quiet`의 `content`를 `two`로 바꾼 뒤 `ignore_changes = [content]` 상태에서 plan했다.

```text
No changes. Your infrastructure matches the configuration.
ignore_changes_plan_exit=0
```

`ignore_changes`는 실제 파일 변경을 되돌리는 기능이 아니다. Terraform이 그 차이를 계획에 넣지 않게 한다.

`terraform plan -destroy`는 구성에 `prevent_destroy = true`가 있는 동안 멈췄다.

```text
Error: Instance cannot be destroyed
Resource local_file.kept has lifecycle.prevent_destroy set, but the plan
calls for this resource to be destroyed.
prevent_destroy_plan_exit=1
```

이 보호는 리소스 블록이 구성에 남아 있을 때 destroy 계획을 막는다. 블록을 지우면 보호가 적용되지 않을 수 있다. 실험에서는 블록을 잠시 빼고 destroy를 실행했다.

```text
Destroy complete! Resources: 2 destroyed.
```

이후 `main.tf`에 `prevent_destroy`를 다시 넣었다. 리소스는 이미 없으므로 빈 State 파일은 지웠다. 지금 `lifecycle/`은 설명용 구성이다. `kept.txt`와 `quiet.txt`는 없다.

## Import가 하는 일

```text
기존 객체
  → import
State에 주소와 ID를 연결
  → plan
코드와 실제 상태를 비교
```

Import는 객체를 State에 연결한다. 기존 설정을 완전한 HCL로 써 주지는 않는다. 교재의 `terraform import local_file.existing <절대경로>`는 현재 Provider에서 실패했다. 빈 `terraform_data`는 Import가 되고, 그 ID로 파일 경로를 기억하게 했다. 파일을 관리하는 리소스는 `local_file`이 아니다. 읽기는 모듈의 `data.local_file`이 한다. 실행 결과는 [04-poc.md](04-poc.md)에 있다.

AWS 예시 `terraform import aws_vpc.existing vpc-...`와 `import` 블록은 그 VPC와 인증이 있을 때만 실행된다. 이번 계정에는 자격 증명이 없어서 실행하지 않았다.

## 보안에서 지킨 것

- HCL에 AWS 액세스 키를 적지 않았다.
- `aws configure`와 임시 자격 증명 설정을 하지 않았다.
- `.gitignore`는 `.terraform/`, `*.tfstate`, `*.tfstate.*`, `*.tfplan`, `*.tfvars`, `crash.log`, override 파일, `.env`, `*.pem`, `*.key`를 제외한다.
- `.terraform.lock.hcl`은 제외하지 않는다. `local` 2.9.1과 `aws` 6.70.0이 잠겨 있다.
- `study.tfplan`, `drift.tfplan`, `import.tfplan`은 확인 후 삭제했다.
- `poc3-aws`에는 `terraform.tfstate`가 없다.
- 프로덕션에서 쓸 IAM 최소 권한과 원격 State 잠금은 문서 기준으로만 확인했다. 적용할 AWS 계정이 없다.
