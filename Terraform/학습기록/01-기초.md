# 기초 — HCL, Provider, Resource

## 왜 코드로 적는가

콘솔에서 VPC와 EC2를 누르면 그 순간의 화면만 남는다. Terraform은 원하는 최종 상태를 HCL로 적고, `plan`으로 차이를 계산한 뒤 `apply`로 맞춘다. 이번 기초는 그 흐름을 AWS 없이 `local_file`로 확인했다.

## CLI

`terraform version` 결과:

```text
Terraform v1.17.0
on darwin_arm64
```

`terraform -help`의 앞부분은 `init`, `validate`, `plan`, `apply`, `destroy`, 그리고 `fmt`, `graph`, `import`를 포함한다. HashiCorp 설치 문서의 최신 버전과 다를 수 있다. 이 머신에는 이미 CLI가 있어서 `brew tap`과 `brew install`은 하지 않았다.

자격 증명 확인:

```text
aws: [ERROR]: An error occurred (NoCredentials): Unable to locate credentials. You can configure credentials by running "aws login".
sts_exit=253
```

`aws configure`는 하지 않았다.

## HCL에서 본 것

문자열, 숫자, 불리언, 리스트, 맵은 그 자체로 `terraform apply`가 되는 구성이 아니다. 실제 구성은 블록이다.

```hcl
resource "TYPE" "NAME" {
  argument = value
}
```

`aws_vpc.study` 같은 주소는 Terraform 구성 안의 이름이다. AWS의 `vpc-...` ID와는 다른 값이다. 기초 실습은 `local_file.study`를 썼다.

## 첫 프로젝트

`fundamentals/`에 `main.tf`, `variables.tf`, `outputs.tf`를 두었다.

- Provider는 `hashicorp/local` `~> 2.5`
- `student_name` 기본값은 `Terraform`
- `local_file.study`는 `hello.txt`에 `Hello, ${var.student_name}!`와 줄바꿈을 쓴다
- `locals.file_label`은 `terraform-study-${var.student_name}`
- `data.local_file.existing`은 그 파일을 읽기만 한다. `depends_on = [local_file.study]`

`terraform init`이 고른 버전:

```text
- Installing hashicorp/local v2.9.1...
- Installed hashicorp/local v2.9.1 (signed by HashiCorp)
Terraform has been successfully initialized!
Success! The configuration is valid.
```

첫 plan:

```text
Plan: 1 to add, 0 to change, 0 to destroy.
file_label = "terraform-study-Terraform"
file_path  = "./hello.txt"
```

plan에는 `local_file.study`가 `+ create`, `data.local_file.existing`이 `<= read`로 나왔다. 파일 권한 기본값은 `file_permission = "0777"`, `directory_permission = "0777"`이었다. 구성에서 권한을 지정하지 않아서 Provider 기본값이 그대로 계획에 보인다.

apply:

```text
local_file.study: Creation complete after 0s [id=ae9c7cc6581fe6b7a01af3ee5fa123a4afc9bac1]
data.local_file.existing: Read complete after 0s [id=ae9c7cc6581fe6b7a01af3ee5fa123a4afc9bac1]
Apply complete! Resources: 1 added, 0 changed, 0 destroyed.
```

`hello.txt` 바이트는 `b'Hello, Terraform!\n'`이다. `terraform output -raw file_content`도 같은 바이트다. `terraform state list`:

```text
data.local_file.existing
local_file.study
```

`terraform state show local_file.study`의 `id`와 `content_sha1`은 둘 다 `ae9c7cc6581fe6b7a01af3ee5fa123a4afc9bac1`이다. 이 Provider에서 파일 ID는 내용의 SHA1이다.

여기서 관리 대상은 파일 이름 문자열이 아니라, `local_file.study`와 그 파일의 관계다. Data Source는 같은 경로를 읽었을 뿐 파일을 새로 만들지 않았다.
