`alpine:3.20`을 받았다.

```text
Digest: sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc
Os=linux Arch=arm64 Size=4103199
디스크 표시: DISK USAGE 13.7MB, CONTENT SIZE 4.17MB
```

RootFS 레이어는 하나다.

```text
sha256:88b4fba61c4c714a2fc173ddf7e9324a257304696830bf41ad28ecc58c11c95f
```

`docker history`에서 파일시스템 변화는 `ADD alpine-minirootfs-3.20.10-aarch64.tar.gz` 9.49MB뿐이다. `CMD ["/bin/sh"]`는 0B다. Dockerfile 명령이 모두 디스크 레이어를 만들지는 않는다.

## study-api 이미지

`fundamentals/app.py`는 8080의 `GET /health`에 JSON을 준다. Dockerfile은 `python:3.12-slim` 위에 uid 10001 `appuser`로 실행한다.

```text
docker build -t study-api:1.0 fundamentals
User=appuser Cmd=["python","-u","app.py"] Exposed={"8080/tcp":{}}
```

history에서 `RUN useradd`는 69.6kB, `COPY app.py`는 12.3kB다. `USER`, `EXPOSE`, `CMD`는 0B다. `EXPOSE`는 문서일 뿐이고 포트를 열지 않는다.

베이스 `python:3.12-slim`은 로컬에 있었다. 다이제스트는 `sha256:a6e34c598f2467ed0e9a8d349809fcd8b5c603269512df273a0bb1784edc11b1`이다.

## 생명주기와 포트

포트를 붙이지 않고 `study-api`를 실행했다. `docker port`는 비어 있었고, `curl http://127.0.0.1:8081/health`는 exit 7, `Couldn't connect to server`였다.

이어서 `-p 127.0.0.1:8081:8080`으로 실행했다. 기동 직후 curl 몇 번은 exit 52 `Empty reply from server`였고, 앱이 받은 뒤에는 다음이 왔다.

```text
{"status": "ok", "hostname": "38719ea521cb"}
uid=10001(appuser) gid=10001(appuser) groups=10001(appuser)
ports=8080/tcp -> 127.0.0.1:8081
```

상태 변화는 `running` → `docker stop` 후 `exited` → `docker start` 후 `running`이다. 호스트 이름은 지정하지 않아서 컨테이너 ID가 UTS 호스트 이름으로 쓰였다.

8080에 붙이려는 실험은 실패가 정답이다.

```text
Bind for 127.0.0.1:8080 failed: port is already allocated
port_conflict_exit=125
```

`lsof`는 `com.docke` PID 73397이 `127.0.0.1:8080`을 듣고 있었다. kind 노드는 그대로 두었다. 그래서 교재의 8080 대신 8081을 썼다.

## Compose

`fundamentals/compose.yaml`도 호스트 포트를 8081로 바꿨다. 컨테이너 안의 헬스 체크는 그대로 `127.0.0.1:8080/health`다.

```text
NAME                 STATUS                    PORTS
fundamentals-api-1   Up (healthy)              127.0.0.1:8081->8080/tcp
{"status": "ok", "hostname": "bab4a8165a12"}
Status=running OOM=false Exit=0 Health=healthy
```

로그에는 헬스 체크의 `127.0.0.1` 요청과, Mac에서 들어온 `172.25.0.1` 요청이 같이 남았다. 확인 후 `docker compose down`으로 이 프로젝트만 지웠다. `-v`는 쓰지 않았고, 이 Compose에는 볼륨이 없다.

## 볼륨과 바인드 마운트

```text
docker volume create study-data
# 첫 컨테이너가 /data/test.txt 에 persistent 를 쓰고 종료
# 다음 컨테이너가 같은 볼륨을 읽음
volume_text=persistent
```

첫 컨테이너는 `--rm`으로 사라졌고 파일은 볼륨에 남았다. 확인 후 `docker volume rm study-data`로 지웠다.

바인드 마운트는 `Docker/shared`를 `/shared`에 읽기 전용으로 연결했다.

```text
bind_text=hello host
sh: can't create /shared/message.txt: Read-only file system
host file still: hello host
```

## Bridge와 DNS

`study-net`에 `server-a`(alpine `sleep`)를 두고 같은 네트워크에서 이름을 찾았다.

```text
PING server-a (172.25.0.2): 56 data bytes
64 bytes from 172.25.0.2: seq=0 ttl=64 time=4.398 ms
64 bytes from 172.25.0.2: seq=1 ttl=64 time=0.424 ms
```

이름은 해석됐지만 `server-a`는 9번 포트에서 아무것도 받지 않는다.

```text
wget: can't connect to remote host (172.25.0.2): Connection refused
```

DNS 성공과 TCP 연결 성공은 별개다.

`isolated-net`에서 같은 이름을 치면 네트워크가 달라서 해석되지 않는다.

```text
ping: bad address 'server-a'
cross_network_exit=1
```

`server-a`, `study-net`, `isolated-net`은 확인 후 삭제했다.
