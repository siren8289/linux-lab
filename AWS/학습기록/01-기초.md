# Part 1. IAM, CLI, VPC

## 4. IAM

Linux의 `rwx`가 파일에 대한 허용이라면, IAM 정책은 AWS API 작업과 리소스 ARN에 대한 허용·거부다. User와 Role은 주체다. `sudo`와 IAM Role은 같은 개념이 아니다. Role은 그 주체가 잠시 맡는 권한 집합이다.

정책 평가는 Identity Policy만 보지 않는다. Resource Policy, SCP, Permission Boundary, Session Policy가 같이 작용할 수 있다. Allow가 하나 있어도 다른 계층의 Deny가 있으면 거절된다.

예제 정책은 객체 읽기만 허용한다.

```json
{
  "Effect": "Allow",
  "Action": ["s3:GetObject"],
  "Resource": "arn:aws:s3:::study-example-bucket/*"
}
```

- `Effect`는 Allow 또는 Deny다.
- `Action`은 API 이름이다.
- `Resource`는 ARN이다. `/*`는 객체 키다. 버킷 목록인 `s3:ListBucket`은 버킷 ARN에 붙는다.
- `s3:PutObject`는 이 문장에 없으므로 이 정책만으로는 허용되지 않는다.

`aws sts get-caller-identity` 결과:

```text
An error occurred (NoCredentials): Unable to locate credentials.
You can configure credentials by running "aws login".
```

`aws configure list`도 access key, secret, region이 비어 있다. `aws configure`는 실행하지 않았다. `simulate-principal-policy`의 `123456789012`는 예시 ARN이라 호출하지 않았다. 같은 판정은 `AWS/poc2-s3/check_policy.py`가 로컬 JSON으로 했다. 그 코드는 Condition, SCP, Permission Boundary를 재현하지 않는다.

## 5. AWS CLI

호출 순서는 터미널 → CLI → API 엔드포인트 → IAM 인가 → 리소스 → JSON이다.

```text
aws <service> <operation> [parameters]
```

자주 쓰는 옵션은 `--region`, `--profile`, `--query`, `--output`, `--endpoint-url`이다. `--dry-run`은 일부 EC2 API에만 있다.

이번 머신에서 계정 API는 자격 증명이 없어 같은 `NoCredentials`로 끝난다. `describe-instances`, `describe-vpcs`는 호출하지 않았다. 로컬 S3는 `--endpoint-url http://127.0.0.1:4566`으로 LocalStack에 보냈다. 자세한 출력은 [04-poc.md](04-poc.md)에 있다.

`jq`는 설치되어 있고, `{"Action":"s3:GetObject"}`를 한 줄 JSON으로 다시 찍었다.

## 6. VPC와 서브넷

VPC `10.0.0.0/16` 안에 다음을 둔다.

| 이름 | CIDR | 역할 | 기본 경로 |
|---|---|---|---|
| public-a | `10.0.1.0/24` | ALB, AZ-a | igw |
| public-b | `10.0.2.0/24` | ALB, AZ-b | igw |
| private-app-a | `10.0.11.0/24` | EC2, AZ-a | nat |
| private-app-b | `10.0.12.0/24` | EC2, AZ-b | nat |
| private-db-a | `10.0.21.0/24` | RDS, AZ-a | 없음 |
| private-db-b | `10.0.22.0/24` | RDS, AZ-b | 없음 |

AWS IPv4 서브넷은 앞 4개와 마지막 1개, 합계 5개를 예약한다. `subnet_check.py` 결과:

```text
10.0.1.0/24 usable: 251
10.0.2.0/24 usable: 251
10.0.11.0/24 usable: 251
10.0.12.0/24 usable: 251
10.0.21.0/24 usable: 251
10.0.22.0/24 usable: 251
PASS: valid VPC subnet design
/24 total=256 aws_usable=251
/26 total=64 aws_usable=59
/28 total=16 aws_usable=11
```

`/28`은 VPC IPv4 서브넷의 최소 크기다. 일반 호스트 계산의 \(2^h-2\)와 달리 AWS 사용 가능 수는 \(2^h-5\)로 세었다.

## 7. Public, Private, 라우트

서브넷 이름이 아니라 `0.0.0.0/0`의 대상이 종류를 만든다.

| 서브넷 | `10.0.0.0/16` | `0.0.0.0/0` |
|---|---|---|
| Public | local | igw |
| Private 앱 | local | nat |
| Private DB | local | 없음 |

Public Subnet에 있다고 EC2가 인터넷에서 바로 열리지는 않는다. 공인 IP, Security Group, NACL, 라우트가 같이 맞아야 한다.

Internet Gateway는 VPC와 인터넷을 잇는다. NAT Gateway는 Private 인스턴스가 밖으로 나갈 때 주소를 바꾼다. NAT는 인터넷에서 시작한 새 연결을 Private EC2로 들여보내는 경로가 아니다.

`aws ec2 describe-route-tables`는 자격 증명이 없어 실행하지 않았다. 같은 규칙은 PoC 1이 설계 데이터에서 검사한다.
