# Part 2. 보안, 서버, 스토리지

## 8. Security Group과 NACL

패킷은 대략 다음 순서로 애플리케이션에 닿는다.

```text
Client → Internet Gateway → Subnet NACL → Security Group → EC2의 로컬 방화벽 → 포트
```

| 구분 | Security Group | Network ACL |
|---|---|---|
| 적용 | ENI | Subnet |
| 상태 | Stateful. 허용한 연결의 응답은 돌아온다 | Stateless. 요청과 응답을 양쪽에 적는다 |
| 규칙 | 허용 규칙의 집합 | 번호 순서의 허용·거부 |
| 반환 트래픽 | 추적된 연결은 자동 허용 | 인바운드와 아웃바운드를 따로 연다 |

실무 예시:

- ALB SG는 인터넷에서 TCP 443만 허용한다.
- EC2 SG는 그 ALB SG에서 온 TCP 8080만 허용한다.
- RDS SG는 그 EC2 SG에서 온 TCP 5432만 허용한다.

8080을 `0.0.0.0/0`에 열면 ALB를 거치지 않는 직접 경로가 생긴다. `describe-security-groups`와 `describe-network-acls`는 계정 자격 증명이 없어 호출하지 않았다.

## 9. EC2

EC2는 AMI, 인스턴스 타입, ENI, Security Group, EBS, IAM Role, User Data로 구성된다. 부팅 뒤 User Data가 돌고, systemd 서비스가 포트를 연다.

이 Mac에서 같은 질문에 해당하는 조회:

```text
uname: Darwin 25.6.0 arm64 (T8140)
sw_vers: macOS 26.6.2, build 25G83
df -h /: /dev/disk3s1s1 460Gi 중 12Gi, APFS
```

`lsblk`, `ip`, `ss`, `systemctl`, `journalctl`은 없다. 이 호스트는 EC2가 아니라서 `describe-instances` 예시의 `i-... t3.micro` 행은 나오지 않는다. 계정에 인스턴스가 없어도 표는 비어 있는 것이 정상인데, 이번엔 그 조회 전에 자격 증명이 없었다.

IMDSv2 토큰 요청:

```text
curl --max-time 2 http://169.254.169.254/latest/api/token
curl: (28) Connection timed out after 2003 milliseconds
```

169.254.169.254는 EC2 안에서만 메타데이터를 준다. 이 Mac에서는 인스턴스 ID를 받지 못했다.

## 10. EBS

EBS는 AZ에 묶인 블록 디스크다. S3는 리전 단위 객체 저장이다.

| 구분 | EBS | S3 |
|---|---|---|
| 형태 | 블록. 파일 시스템을 올린다 | 객체. API와 HTTP |
| 주로 담는 것 | OS, DB 파일 | 이미지, 백업, 정적 파일 |
| 범위 | 한 AZ | 리전 서비스. VPC 소속 리소스가 아님 |

Nitro 인스턴스에서는 EBS가 `nvme0n1`처럼 보인다. 이 Mac의 `/`는 APFS `disk3s1s1`이다. `gp3`는 크기와 IOPS·처리량을 어느 범위에서 따로 둔다. 느릴 때는 용량만 보지 않고 IOPS, 처리량, 지연을 나눈다.

`describe-volumes`는 자격 증명이 없어 호출하지 않았다.

## 11. S3

`images/logo.png`는 폴더가 아니라 객체 키 전체다. `/`는 콘솔이 폴더처럼 보이게 하는 구분자다.

버킷, 객체, 키, Versioning, Lifecycle, Bucket Policy, Block Public Access가 핵심이다. Block Public Access는 실수로 공개되는 것을 막는다.

실제 버킷 `MY-BUCKET`은 만들지 않았다. 로컬 검증은 LocalStack Community `4.9.2`의 S3 API다. 업로드와 다운로드 결과, SHA-256이 같다는 증거는 [04-poc.md](04-poc.md)에 있다.
