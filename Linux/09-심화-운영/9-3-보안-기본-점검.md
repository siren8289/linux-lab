# 9-3. Linux 보안 기본 점검

## 목적

실행 중인 서비스, 수신 포트, 방화벽, SSH 로그인, 강제 접근 제어, 아직 적용하지 않은 패키지 업데이트를 한 번에 훑는다. 포트만 열거하지 않고, 그 포트를 연 프로세스와 방화벽 상태를 같이 적는다.

리눅스에서 각 명령이 보여 주는 것은 다음과 같다.

| 명령 | 읽는 것 |
|---|---|
| `systemctl --type=service --state=running` | 실행 중인 systemd 서비스 |
| `sudo ss -lntup` | LISTEN 중인 TCP/UDP와 프로세스. `-p`는 root가 필요할 때가 많다 |
| `sudo ufw status verbose` | 방화벽 기본 정책과 허용 규칙 |
| `sudo journalctl -u ssh -n 50 --no-pager` | SSH 유닛의 최근 50줄 |
| `sudo aa-status` | AppArmor 프로필이 enforce인지 complain인지 |
| `apt list --upgradable` | 아직 올리지 않은 패키지 |

## 실행한 명령

```bash
systemctl --type=service --state=running
sudo -n ss -lntup
sudo -n ufw status verbose
sudo -n journalctl -u ssh -n 50 --no-pager
sudo -n aa-status
apt list --upgradable
```

호스트에서 확인 가능한 항목은 아래로 대신 보았다.

```bash
lsof -nP -iTCP -sTCP:LISTEN
/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate
lsof -nP -iTCP:22 -sTCP:LISTEN
```

## 결과

| 명령 | 결과 |
|---|---|
| `systemctl ...` | `command not found: systemctl` |
| `sudo -n ss -lntup` | `sudo: a password is required`. `ss`도 없다 |
| `sudo -n ufw status verbose` | `sudo: a password is required`. `ufw`도 없다 |
| `sudo -n journalctl -u ssh ...` | `sudo: a password is required`. `journalctl`도 없다 |
| `sudo -n aa-status` | `sudo: a password is required`. `aa-status`도 없다 |
| `apt list --upgradable` | `command not found: apt` |

### 수신 포트

`lsof -nP -iTCP -sTCP:LISTEN` 기준이다. UDP는 이 명령에 포함되지 않는다.

모든 인터페이스(`*`)에서 수신:

| 프로세스 | 포트 |
|---|---|
| ControlCenter | 5000, 7000 (IPv4와 IPv6) |
| rapportd | 55288 (IPv4와 IPv6) |
| mysqld | 3306, 33060 |

루프백에서만 수신:

| 프로세스 | 포트 |
|---|---|
| postgres | 5432 (`127.0.0.1`, `::1`) |
| com.docke (PID 73397) | 8000, 8080, 8443, 54600, 58472 |
| figma_agent | 44950, 44960 |
| Notion | 50621, 57599 |
| Google Chrome | `[::1]:7679` |
| Orca | 50351, 6768 |
| Readray | 27110 |
| agy | 51935, 51936, 62396, 62397 |

Docker가 연 루프백 포트는 이 세션에서 확인한 컨테이너 공개 포트와 같다.

| 호스트 포트 | 컨테이너 |
|---|---|
| 127.0.0.1:8080 → 80 | `gitops-lab-control-plane` (kind) |
| 127.0.0.1:8443 → 443 | 같은 kind 노드 |
| 127.0.0.1:54600 → 6443 | 같은 kind 노드 |
| 127.0.0.1:58472 → 6443 | `cloud-poc-control-plane` |
| 127.0.0.1:8000 → 8000 | `cloud-ops-lab-api` |

ControlCenter의 5000/7000은 macOS AirPlay Receiver, rapportd는 연속성(Continuity) 관련 시스템 프로세스다. 모든 인터페이스에 열려 있다는 사실 자체만으로 이 둘을 MySQL과 같은 종류의 노출로 적지는 않는다.

### 방화벽과 SSH

```text
Firewall is disabled. (State = 0)
nothing listening on tcp/22
```

애플리케이션 방화벽은 꺼져 있다. TCP 22에는 수신 프로세스가 없으므로, SSH 로그인 저널을 열어도 이 호스트의 `sshd` 접속 기록은 없을 상태다.

## 배운 점

- 수신 표는 "포트 번호"와 "어느 주소에 붙었는지"와 "프로세스 이름"을 같이 적어야 한다. 3306이 `*`이면 루프백만 듣는 5432와 노출 범위가 다르다.
- 이번 점검에서 같이 적을 문장은 이것이다. `mysqld`가 3306과 33060을 모든 인터페이스에서 수신하고, 애플리케이션 방화벽은 꺼져 있다. 데이터베이스를 이 Mac 안에서만 쓸 계획이었다면 다음 확인 항목은 MySQL의 bind 주소다.
- Docker 포트가 `127.0.0.1`에만 있는 것은 호스트 밖에서는 그 포트로 바로 접속하지 못한다는 뜻이다.
- 패키지 업데이트 목록은 `apt`가 없어 만들지 못했다. 패치 공백은 이번 기록에서 미확인이다.
- AppArmor, PAM, 파일 ACL, umask, sudoers, sysctl, LVM, RAID, 프로세스 자원 제한은 이번 호스트에서 명령을 실행하지 못했다. 이름만 알아 둘 확장은 다음과 같다.
  - cgroups는 프로세스 그룹의 CPU·메모리 상한이다.
  - namespaces는 프로세스 ID, 네트워크, 마운트를 격리한다.
  - Docker와 Kubernetes는 이 둘 위에 컨테이너를 만든다. kind 노드 안의 80번이 자기 네트워크 namespace에 있고, 호스트에는 공개된 `127.0.0.1:8080`만 보이는 것이 그 예다.

## 이 절의 트러블슈팅

### Problem

`systemctl`, `ss`, `ufw`, `journalctl`, `aa-status`, `apt`로 교재의 보안 점검 표를 채울 수 없었다. 일부는 명령이 없고, `sudo`가 필요한 항목은 비밀번호 없이 실행되지 않았다.

### 해결한 방법

상태를 바꾸지 않고, 이미 가능한 조회로 대체했다. TCP 수신은 `lsof -nP -iTCP -sTCP:LISTEN`, 방화벽은 `socketfilterfw --getglobalstate`, SSH 수신 여부는 `lsof`로 22번만 확인했다. Docker 포트의 주인은 `docker ps`의 공개 포트와 PID 73397을 맞춰 적었다.

### Result

systemd 서비스 목록, ufw 규칙, SSH 저널, AppArmor 프로필, apt 업데이트 목록은 비어 있다. 대신 TCP 수신 표, 방화벽 꺼짐, TCP 22 미사용, MySQL의 `*:3306`/`*:33060`을 기록했다.

### Problem

`sudo ss -lntup`를 그대로 두면 비밀번호 입력에서 멈춘다.

### 해결한 방법

`sudo -n`으로 비대화 실행했다. 실패하면 바로 다음 명령으로 넘어가게 했다.

### Result

`sudo: a password is required`. 포트 조사는 `lsof` 결과로 계속했다.
